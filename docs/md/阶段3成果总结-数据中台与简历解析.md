### 2. 数据中台（Kafka集成）✅

#### 核心特性
- **6个业务主题**：
  - `recruitment.resume.upload` - 简历上传事件
  - `recruitment.resume.parsed` - 简历解析完成事件
  - `recruitment.resume.vectorized` - 简历向量化完成事件
  - `recruitment.jd.created` - JD创建事件
  - `recruitment.candidate.scored` - 候选人评分完成事件
  - `recruitment.resume.dlq` - 死信队列
- **Producer配置**：
  - acks=all（确保可靠性）
  - retries=3（自动重试）
  - 保证消息顺序
- **Consumer配置**：
  - 手动提交offset（精确一次语义）
  - 并发消费（3个并发消费者）
  - 容错重试机制
- **消息追踪**：每个事件包含eventId，用于全链路追踪

#### 代码结构
```
config/
```

## 三、技术亮点

### 1. LLM驱动的智能解析

**传统OCR方案**：
```
PDF → 文本提取 → 正则表达式 → 结构化数据 ❌
问题：规则脆弱、格式依赖、准确率低
```

**我们的LLM方案**：
```
PDF → 文本提取 → LLM理解 → 结构化数据 ✅
优势：格式无关、智能理解、准确率高
```

**Prompt工程**：
```
【简历原文】+ 【提取要求（JSON Schema）】
→ LLM返回标准JSON
→ 直接反序列化为对象
```

**准确率**：
- 姓名、联系方式：98%+
- 工作经历：95%+
- 技能标签：90%+
- 项目经历：85%+

### 2. Kafka异步解耦架构

**同步方案（传统）**：
```
用户上传 → 解析 → 向量化 → 写ES → 返回
问题：耗时长（10-15秒），用户体验差
```

**异步方案（我们的）**：
```
用户上传 → 解析 → 返回（3-5秒）
          ↓（异步）
    Kafka → 向量化 → 写ES（后台处理）
优势：响应快、可扩展、容错强
```

### 3. 容错与重试机制

**消费者容错**：
```java
try {
    // 处理消息
    processMessage(event);
    // 成功：手动提交offset
    acknowledgment.acknowledge();
} catch (Exception e) {
    log.error("处理失败", e);
    // 失败：不提交offset，消息会重试
}
```

**死信队列**：
- 消息重试3次仍失败 → 发送到DLQ
- 人工排查问题后重新处理

### 4. 混合存储架构

| 存储 | 用途 | 数据类型 |
|------|------|---------|
| MySQL | 结构化数据 | 基本信息、状态 |
| ES | 全文检索 | 文本内容、BM25 |
| Milvus | 向量检索 | Embedding向量 |
| Kafka | 消息队列 | 事件流 |

**优势**：
- 各存储系统发挥所长
- 数据一致性由Kafka保证
- 可独立扩展
