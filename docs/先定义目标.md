# 先定义目标：

# 我要做一个企业级的智能招聘Agent，如果做，需要哪些技术，工作流程是什么

## 一、先定义目标：不是“招聘聊天机器人”

如果你要做的是**企业级智能招聘 Agent**，我建议不要把它设计成一个“大模型 \+ RAG”的项目，而是设计成：

> **招聘业务系统 \+ 多 Agent 协作 \+ 企业知识库 \+ 招聘数据中台 \+ 工作流引擎 \+ Tool Calling \+ RAG \+ 人机协同**
> 
> 

最终目标是让 Agent 能够完成：

```Plain Text
招聘需求
  ↓
理解招聘需求
  ↓
生成/优化 JD
  ↓
自动搜索候选人
  ↓
简历解析
  ↓
候选人匹配
  ↓
候选人排序
  ↓
AI 初筛
  ↓
AI 沟通
  ↓
邀约面试
  ↓
面试安排
  ↓
面试辅助
  ↓
面试评价
  ↓
候选人推荐
  ↓
Offer
  ↓
入职
  ↓
招聘效果分析
```

真正企业级的核心不是“会回答问题”，而是：

> **Agent 能不能理解招聘业务目标，并自主调用企业系统完成一系列招聘动作。**
> 
>

# 八、Screening Agent

这是企业级系统真正有价值的地方。

不是：

> “这个人怎么样？”
> 
> 

而是：

```Plain Text
岗位要求
      ↓
Candidate Profile
      ↓
规则引擎
      ↓
LLM分析
      ↓
匹配评分
      ↓
风险分析
      ↓
推荐结论
```

建议把评分拆成：

```Plain Text
硬性条件      30%
技能匹配      25%
工作经验      15%
行业经验      10%
项目经验      10%
薪资匹配      5%
稳定性        5%
```

而且：

> **硬性条件不能交给 LLM 自由发挥。**
> 
> 

例如：

```Plain Text
学历必须本科
```

应该由规则引擎直接判断。

LLM负责：

```Plain Text
项目质量
技术深度
职业发展
岗位匹配度
```

这样才能做到企业级。


```Plain Text

```


然后：

```Plain Text

你好，薪资是多少？

根据岗位信息回答……

我目前在职。

Agent：
询问预计离职周期……

两个月。

Agent：
记录 notice_period = 60 days
```

这就是：

> **Agent \+ Tool Calling \+ 状态机**
> 
> 

而不是简单聊天。

# 四、StateGraph 怎么设计

## 不要让 Agent 自由发挥

```Python

    task_id: int

    job_id: int

    requirement: dict

    search_query: dict

    candidate_ids: list[int]

    candidates: list[dict]

    scores: list[dict]

    selected_candidates: list[int]

    current_candidate_id: int | None

    conversation: list[dict]

    next_action: str

    human_approval: bool

    error: str | None
```

然后：

```Plain Text
START
  ↓
parse_requirement
  ↓
build_search_query
  ↓
search_candidates
  ↓
rerank_candidates
  ↓
screen_candidates
  ↓
score_candidates
  ↓
human_review
  ↓
┌───────────────┐
│               │
通过            拒绝
│               │
▼               ▼
contact       END
│
▼
wait_response
│
▼
analyze_response
│
▼
schedule_interview
│
▼

```

这就是企业级 Agent 最重要的东西：

# 五、Agent 和 StateGraph 的关系

所以：


# 十一、候选人评分系统

我建议采用：

```Plain Text
Hard Filter
     ↓
Rule Score
     ↓
LLM Score
     ↓
Rerank Score
     ↓
Final Score
```

```Plain Text

硬性条件        30%
技能匹配        25%
项目经验        15%
工作经验        10%

```


```Plain Text

其他得分90
最终75
```

否则企业招聘场景很容易出现明显错误。

# 十、Scoring Engine

我们把评分从 LLM 中独立出来。

```Python
class CandidateScorer:

    def score(
        self,
        candidate: dict,
        requirement: dict
    ) -> dict:

        # 1. 硬条件
        if (
            requirement.get("experience_min")
            and candidate["experience_years"]
            < requirement["experience_min"]
        ):
            return {
                "score": 0,
                "recommendation": "REJECT",
                "reason": "工作年限不满足"
            }

        score = 0

        # 2. 技能
        required_skills = set(
            requirement.get("skills", [])
        )

        candidate_skills = set(
            candidate.get("skills", [])
        )

        if required_skills:
            skill_score = (
                len(
                    required_skills
                    & candidate_skills
                )
                / len(required_skills)
            )

            score += skill_score * 40

        return {
            "score": round(score, 2),
            "recommendation": (
                "RECOMMEND"
                if score >= 70
                else "REVIEW"
            )
        }
```

# 十一、现在把它们放进 StateGraph

这是整个 V1 最关键的一步。

```Python
from langgraph.graph import StateGraph, START, END

from app.schemas.recruitment import RecruitmentState


def create_recruitment_graph(
    planner,
    search_tool,
    screening_agent,
    scorer
):

    graph = StateGraph(
        RecruitmentState
    )

    async def planner_node(state):

        requirement = await planner.run(
            state["user_query"]
        )

        return {
            "requirement": requirement.model_dump(),
            "current_node": "planner"
        }

    async def search_node(state):

        requirement = state["requirement"]

        candidates = await search_tool.ainvoke(
            {
                "position": requirement["position"],
                "location": requirement.get("location"),
                "experience_min": requirement.get(
                    "experience_min"
                ),
                "skills": requirement.get(
                    "skills"
                ),
                "limit": 20
            }
        )

        return {
            "candidates": candidates,
            "candidate_ids": [
                x["candidate_id"]
                for x in candidates
            ],
            "current_node": "search"
        }

    async def screening_node(state):

        result = await screening_agent.run(
            state["requirement"],
            state["candidates"]
        )

        return {
            "screened_candidates": result,
            "current_node": "screening"
        }

    async def scoring_node(state):

        scored = []

        for candidate in state[
            "candidates"
        ]:

            score = scorer.score(
                candidate,
                state["requirement"]
            )

            scored.append({
                **candidate,
                **score
            })

        scored.sort(
            key=lambda x: x["score"],
            reverse=True
        )

        return {
            "scored_candidates": scored,
            "recommended_candidates": scored[:10],
            "current_node": "scoring"
        }

    graph.add_node(
        "planner",
        planner_node
    )

    graph.add_node(
        "search",
        search_node
    )

    graph.add_node(
        "screening",
        screening_node
    )

    graph.add_node(
        "scoring",
        scoring_node
    )

    graph.add_edge(
        START,
        "planner"
    )

    graph.add_edge(
        "planner",
        "search"
    )

    graph.add_edge(
        "search",
        "screening"
    )

    graph.add_edge(
        "screening",
        "scoring"
    )

    graph.add_edge(
        "scoring",
        END
    )

    return graph.compile()
```

现在已经有第一条完整 Agent Workflow 了。

# 六、ES SearchService

项目：

```Plain Text

```

```Python
class ElasticsearchRetriever:

    def __init__(self, client, index: str):
        self.client = client
        self.index = index

    async def search(
        self,
        requirement: dict,
        limit: int = 100
    ):

        filters = []

        if requirement.get("location"):
            filters.append({
                "term": {
                    "location": requirement["location"]
                }
            })

        if requirement.get("experience_min") is not None:
            filters.append({
                "range": {
                    "experience_years": {
                        "gte": requirement[
                            "experience_min"
                        ]
                    }
                }
            })

        if requirement.get("salary_max") is not None:
            filters.append({
                "range": {
                    "expected_salary": {
                        "lte": requirement[
                            "salary_max"
                        ]
                    }
                }
            })

        skills = requirement.get(
            "skills",
            []
        )

        should = []

        for skill in skills:
            should.append({
                "match": {
                    "resume_text": skill
                }
            })

        body = {
            "size": limit,
            "query": {
                "bool": {
                    "filter": filters,
                    "should": should,
                    "minimum_should_match": 0
                }
            }
        }

        response = await self.client.search(
            index=self.index,
            body=body
        )

        return response["hits"]["hits"]
```

# 十四、RRF

第一版推荐 RRF：

```Plain Text
Reciprocal Rank Fusion
```

公式：

```Plain Text
RRF(d) =
Σ 1 / (k + rank(d))
```

例如：

```Plain Text

```

候选人：

```Plain Text
A
ES rank = 1
Milvus rank = 2
```

那么：

```Plain Text
1 / 61
+
1 / 62
```

而：

```Plain Text
E
ES没有
Milvus rank = 3
```

那么：

```Plain Text
1 / 63
```

A自然会排在E前面。

# 十五、RRF代码

```Python
def reciprocal_rank_fusion(
    result_lists: list[list[int]],
    k: int = 60
) -> list[tuple[int, float]]:

    scores = {}

    for result_list in result_lists:

        for rank, candidate_id in enumerate(
            result_list,
            start=1
        ):

            scores[candidate_id] = (
                scores.get(candidate_id, 0)
                + 1 / (k + rank)
            )

    return sorted(
        scores.items(),
        key=lambda x: x[1],
        reverse=True
    )
```

# 十九、最终 CandidateSearchService

```Python
class CandidateSearchService:

    def __init__(
        self,
        es_retriever,
        milvus_retriever,
        reranker
    ):
        self.es = es_retriever
        self.milvus = milvus_retriever
        self.reranker = reranker

    async def search(
        self,
        requirement: dict,
        top_k: int = 20
    ):

        query = self._build_query(
            requirement
        )

        es_results = await self.es.search(
            requirement,
            limit=100
        )

        vector_results = (
            await self.milvus.search(
                query,
                limit=100
            )
        )

        es_ids = [
            item["candidate_id"]
            for item in es_results
        ]

        vector_ids = [
            item["candidate_id"]
            for item in vector_results
        ]

        fused = reciprocal_rank_fusion(
            [
                es_ids,
                vector_ids
            ]
        )

        candidate_ids = [
            candidate_id
            for candidate_id, score in fused[:50]
        ]

        candidates = await self.load_candidates(
            candidate_ids
        )

        reranked = await self.reranker.rerank(
            query,
            candidates,
            top_k
        )

        return reranked
```

```Plain Text
最终分 = 技能×40% + 经验×20% + 项目×15% + 行业×10% + 薪资×10% + 稳定性×5%
```



问题立刻出现：



1. **硬性条件被平均掉**

岗位要求 Java ≥ 5 年，候选人只有 3 年 → 经验分低，但其他项高，最终可能还到 70\+，被推荐。



2. **分数不可解释**

HR 问“为什么 92？”系统只能说“综合计算”。



3. **偏好无法注入**

某个招聘经理特别看重“大厂 \+ 高并发”，另一个更看重“稳定性”，同一套权重无法适应。



4. **风险被淹没**

频繁跳槽、薪资倒挂、项目水分大，被平均分掩盖。



5. **无法审计**

出了问题不知道是规则错了、Embedding 偏了，还是 LLM 幻觉。



企业级原则：



> **硬性条件 = 过滤器（Filter）**  
> 
> **规则分 = 可解释基础分**  
> 
> **语义/LLM = 软性洞察与风险**  
> 
> **偏好 = 可配置加权**  
> 
> **最终推荐 = 分数 \+ 理由 \+ 风险 \+ 人工可覆盖**
> 
>

## 四、Hard Constraint（一票否决）



**永远不要交给 LLM。**



```Python
class HardConstraintFilter:

    def check(
        self,
        candidate: dict,
        requirement: dict
    ) -> dict:
        reasons = []

        # 经验
        exp_min = requirement.get("experience_min")
        if exp_min is not None:
            if (candidate.get("experience_years") or 0) < exp_min:
                reasons.append(f"工作年限不足：要求≥{exp_min}年，实际{candidate.get('experience_years')}年")

        # 地点
        loc = requirement.get("location")
        if loc and candidate.get("location") != loc:
            # 可根据业务决定是否严格
            reasons.append(f"工作地点不匹配：要求{loc}，候选人{candidate.get('location')}")

        # 薪资上限
        salary_max = requirement.get("salary_max")
        expected = candidate.get("expected_salary")
        if salary_max and expected and expected > salary_max * 1.1:  # 允许10%浮动
            reasons.append(f"期望薪资超标：上限{salary_max}，期望{expected}")

        # 学历
        edu_req = requirement.get("education")
        if edu_req and not self._edu_match(candidate.get("education"), edu_req):
            reasons.append(f"学历不满足：要求{edu_req}")

        # 自定义硬性条件（来自 Planner 或 Preference）
        for constraint in requirement.get("hard_constraints", []):
            if not self._rule_match(candidate, constraint):
                reasons.append(f"硬性条件不满足：{constraint}")

        if reasons:
            return {
                "hard_pass": False,
                "hard_fail_reasons": reasons,
                "recommendation": "REJECT",
                "final_score": 0.0
            }

        return {"hard_pass": True, "hard_fail_reasons": []}
```



原则：



- 硬条件失败 → 直接 REJECT，不进入后续评分。

- 所有失败原因必须落库，方便审计与 HR 查看。

## 五、Rule Engine（确定性基础分）



规则分必须**可复现、可单测、可解释**。



```Python
class RuleScorer:

    def score(
        self,
        candidate: dict,
        requirement: dict,
        preference: dict | None = None
    ) -> dict:

        weights = (preference or {}).get("weights", {
            "skill": 0.35,
            "experience": 0.20,
            "project": 0.20,
            "industry": 0.10,
            "salary": 0.05,
            "stability": 0.05,
            "location": 0.05
        })

        skill_score = self._skill_score(candidate, requirement)
        exp_score = self._experience_score(candidate, requirement)
        project_score = self._project_score(candidate, requirement)
        industry_score = self._industry_score(candidate, requirement)
        salary_score = self._salary_score(candidate, requirement)
        stability_score = self._stability_score(candidate)
        location_score = self._location_score(candidate, requirement)

        base = (
            skill_score * weights["skill"] +
            exp_score * weights["experience"] +
            project_score * weights["project"] +
            industry_score * weights["industry"] +
            salary_score * weights["salary"] +
            stability_score * weights["stability"] +
            location_score * weights["location"]
        ) * 100

        return {
            "rule_score": round(base, 2),
            "skill_score": round(skill_score * 100, 2),
            "experience_score": round(exp_score * 100, 2),
            "project_score": round(project_score * 100, 2),
            "industry_score": round(industry_score * 100, 2),
            "salary_score": round(salary_score * 100, 2),
            "stability_score": round(stability_score * 100, 2),
            "location_score": round(location_score * 100, 2),
        }

    def _skill_score(self, candidate, requirement):
        required = set(requirement.get("skills", []))
        if not required:
            return 1.0
        cand = set(candidate.get("skills", []))
        # 精确匹配 + 同义词扩展可在 Normalizer 层完成
        intersection = required & cand
        return len(intersection) / len(required)

    def _experience_score(self, candidate, requirement):
        min_exp = requirement.get("experience_min") or 0
        years = candidate.get("experience_years") or 0
        if years >= min_exp + 3:
            return 1.0
        if years >= min_exp:
            return 0.85 + 0.05 * (years - min_exp)
        return max(0.0, years / max(min_exp, 1))

    def _stability_score(self, candidate):
        # 根据跳槽频率、平均在职时长计算
        hops = candidate.get("job_change_count_last_5y", 0)
        if hops >= 4:
            return 0.3
        if hops == 3:
            return 0.6
        if hops <= 1:
            return 1.0
        return 0.8
```



关键点：



- 所有分项都落库。

- 权重来自 `recruiter_preference`，可按岗位族/招聘经理配置。

- 规则可单测，不依赖 LLM。

## 六、Semantic / Rerank 信号融入



上一课 Hybrid Search 已经产出：



- `es_score`

- `vector_score`

- `rerank_score`

    

在评分阶段把它们作为**软信号**，而不是直接当最终分：



```Python
def fuse_semantic(
    rule_score: float,
    rerank_score: float | None,
    weight_semantic: float = 0.25
) -> float:
    if rerank_score is None:
        return rule_score
    # 归一化后加权
    semantic = min(max(rerank_score, 0.0), 1.0) * 100
    return rule_score * (1 - weight_semantic) + semantic * weight_semantic
```



这样：



- 规则保证“基本面正确”

- Rerank 保证“语义上更像岗位描述”

## 八、Preference Adjustment（HR 偏好驱动）



```Python
def apply_preference(
    base_score: float,
    candidate: dict,
    preference: dict
) -> float:
    score = base_score
    boosts = preference.get("boost", {})
    penalties = preference.get("penalty", {})

    if candidate.get("has_big_tech"):
        score += boosts.get("big_tech_experience", 0)
    if candidate.get("has_high_concurrency"):
        score += boosts.get("high_concurrency_project", 0)
    if candidate.get("job_hopping_frequent"):
        score += penalties.get("job_hopping_frequent", 0)
    # ... 更多规则

    return max(0.0, min(100.0, score))
```



这样同一候选人，不同 HR 可以看到不同最终分，同时**所有调整都有记录**。

## 九、最终组装：CandidateScoringService



```Python
class CandidateScoringService:

    def __init__(
        self,
        hard_filter,
        rule_scorer,
        llm_scorer,
        preference_repo
    ):
        self.hard_filter = hard_filter
        self.rule_scorer = rule_scorer
        self.llm_scorer = llm_scorer
        self.preference_repo = preference_repo

    async def score(
        self,
        task_id: int,
        job_id: int,
        candidate: dict,
        requirement: dict,
        recruiter_id: int,
        semantic_signals: dict | None = None
    ) -> dict:

        # 1. Hard
        hard = self.hard_filter.check(candidate, requirement)
        if not hard["hard_pass"]:
            return self._build_reject(hard, candidate)

        # 2. Rule
        preference = await self.preference_repo.get_active(
            recruiter_id, requirement.get("position")
        )
        rule = self.rule_scorer.score(candidate, requirement, preference)

        # 3. Semantic fuse
        rule_score = rule["rule_score"]
        semantic_score = None
        if semantic_signals:
            semantic_score = semantic_signals.get("rerank_score")
            rule_score = fuse_semantic(rule_score, semantic_score)

        # 4. LLM
        llm_result = await self.llm_scorer.analyze(
            candidate, requirement, rule
        )

        # 5. 融合
        blended = (
            rule_score * 0.55 +
            (semantic_score or rule_score) * 0.20 +
            llm_result["llm_score"] * 0.25
        )

        # 6. Preference
        final = apply_preference(blended, candidate, preference or {})

        # 7. 推荐决策
        recommendation = self._decide(final, llm_result, hard)

        return {
            "task_id": task_id,
            "job_id": job_id,
            "candidate_id": candidate["candidate_id"],
            "final_score": round(final, 2),
            "recommendation": recommendation,
            "hard_pass": True,
            "rule_score": rule["rule_score"],
            "semantic_score": semantic_score,
            "llm_score": llm_result["llm_score"],
            "preference_adjusted_score": round(final, 2),
            **{k: rule[k] for k in [
                "skill_score", "experience_score", "project_score",
                "industry_score", "salary_score", "stability_score", "location_score"
            ]},
            "strengths": llm_result["strengths"],
            "risks": llm_result["risks"],
            "explanation": llm_result["match_summary"],
            "llm_analysis": llm_result,
            "preference_version": preference.get("version") if preference else None,
            "scorer_version": "2.0.0"
        }
```

## 第10课：Human\-in\-the\-loop \+ Checkpoint 生产化



上一课我们完成了可解释、可审计、可偏好驱动的 Candidate Scoring 2\.0。



现在评分结果已经出来，但企业级系统绝不能让 Agent 自动联系所有人、自动约面、自动发 Offer。



本课把“人机协同”从概念变成可上线的生产能力：



```Plain Text
Scoring
  ↓
创建 Approval 记录（MySQL）
  ↓
LangGraph Checkpoint 持久化
  ↓
Graph 暂停（interrupt）
  ↓
前端展示推荐列表 + 分数卡片
  ↓
HR 批准 / 拒绝 / 部分通过 / 调整分数
  ↓
API 恢复 Graph（resume）
  ↓
继续执行（Communication 或 END）
```

### 一、核心原则



1. **高风险动作必须人工确认**（联系候选人、约面、发 Offer、改薪资）。

2. **Graph 必须可暂停、可恢复、可长时间等待**（HR 可能隔天再审）。

3. **审批状态必须落库**，不能只存在内存。

4. **支持部分通过**（推荐 20 人，HR 只批 12 人）。

```Python
async def resume_after_approval(
    task_id: int,
    approval_id: int,
    action: str,
    selected_ids: list[int] | None,
    comment: str | None,
    reviewer_id: int
):
    # 1. 更新审批记录
    await approval_repo.update_status(...)

    # 2. 准备 resume 的 state update
    update = {
        "approved": action in ("APPROVE", "PARTIAL"),
        "approval_status": action,
        "selected_candidate_ids": selected_ids or [],
        "approval_comment": comment,
        "reviewer_id": reviewer_id
    }

    # 3. 恢复 Graph
    config = {"configurable": {"thread_id": f"recruitment-task-{task_id}"}}
    await graph.ainvoke(update, config=config)
```
