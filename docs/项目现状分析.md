## 一、项目概览

### 1.1 目标定位
根据 `docs/先定义目标.md` 文档，本项目目标是构建一个**企业级智能招聘Agent系统**，而非简单的"招聘聊天机器人"。

核心能力包括：
- 招聘需求理解 → JD生成/优化
- 候选人搜索 → 简历解析
- 候选人评分 → 面试安排
- 面试评价 → Offer生成
- 数据中台 + 人机协同

## 四、架构缺陷与风险

### 4.1 当前架构问题

1. **单一检索通道**
   - 仅依赖向量检索，缺乏关键词检索兜底
   - 风险：语义理解偏差时召回率低

2. **缺乏数据中台**
   - 无Kafka异步解耦
   - 无ES增量索引
   - 风险：高并发下数据库压力大、索引更新慢

3. **无评分引擎**
   - 无法量化候选人匹配度
   - 无法支持HR偏好配置
   - 风险：推荐结果不可解释、不可优化

4. **Python服务简陋**
   - 意图识别准确率未验证
   - HDBSCAN聚类效果未评估
   - 风险：误判用户意图导致错误流程

5. **无人机协同机制**
   - 所有决策由AI自动完成
   - 无HR审核环节
   - 风险：法律风险、错误决策无法纠正

### 4.2 性能风险

| 风险点 | 描述 | 影响 |
|--------|------|------|
| PDF解析同步阻塞 | 上传大文件时占用请求线程 | 高并发下线程池耗尽 |
| 向量化串行执行 | 每个chunk依次调用Embedding API | 处理速度慢 |
| Milvus单点故障 | 无高可用配置 | 系统不可用 |
| 无缓存策略 | 重复查询无缓存 | 响应慢、成本高 |

## 七、风险与建议

### 7.1 关键风险
1. **LLM成本**：频繁调用qwen-plus成本较高
   - 建议：结果缓存 + 使用DeepSeek备用

2. **数据安全**：简历数据敏感
   - 建议：数据脱敏 + 访问审计 + 加密存储

3. **法律合规**：AI招聘决策的法律责任
   - 建议：人机协同 + 决策可审计 + 免责声明

### 7.2 优化建议
1. **渐进式开发**：先完善核心RAG，再扩展业务功能
2. **数据驱动**：建立评测数据集，量化优化效果
3. **用户反馈**：早期引入HR试用，收集真实反馈
4. **模块解耦**：各业务模块独立服务化，便于迭代
